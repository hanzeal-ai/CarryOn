# 会话过程呈现修正

## 当前契约

以用户提供的两张 Codex 截图为视觉依据：用户消息 → 可折叠的本轮过程 → 最终回答。展开的过程保留原始顺序，以灰色单行活动和 Agent 名称加动作呈现；移除重复的状态徽标、活动类型标题及轮次完成时间行。审批、未回答的问题、异常和生成图片仍可见。

风险 R1：仅修改 iOS 展示投影及视图；不改 IPC、消息、审批、队列写入和权限契约。主会话与已有临时聊天共用投影。保留当前工作区其他未提交改动。

## 实现

- `ConversationProcess` 依据原生 turnId 和正文边界组织阶段；所有 agentMessage（含 commentary）独立显示，文字前后的调用各自形成过程阶段。
- 过程运行时自动展开，首行优先显示仍在执行的具体命令或思考步骤（支持 Markdown），后续正文结束当前阶段，后面的调用开启新阶段。每个阶段的展开列表独立限高 280pt，短内容按实际高度，溢出仅内部滚动；首行位于滚动容器外。最终回答开始输出或本轮结束时收起；单阶段可显示原生 durationMs；多阶段不把整轮耗时复制成每阶段耗时，未提供阶段耗时则显示“运行命令、修改文件”等阶段活动摘要。单条调用直接显示调用行，避免重复标题；单独思考摘要没有空展开入口。
- 普通活动使用小图标与灰色单行描述。下方直接列出具体命令、文件变更、搜索和 Agent 活动，不再二次折叠。思考步骤只用于首行摘要，不重复列入下方列表。
- Agent 活动以“名称 有更新/已结束/正在执行”等自然动作描述呈现，保留原有入口及只读限制。
- 错误、未回答的异步问题、图片输出、最终回答及本轮 diff 不藏入过程；审批与队列入口继续由输入区旁的已有面板提供。
- 展开状态复用会话级保存机制；返回父会话仍使用过程行锚点。命令详情保留完整输出、复制及真实执行状态。

- 左上角角标直接消费服务端 `excludeThreadId` 后的数量，当前会话完成不会进入该数字；其他会话仍正常提示。全局动态数量单独保留，迟到统计需匹配设备作用域及当前会话。

## 摘要修正

- 过程标题和活动摘要复用 Markdown 行内渲染，`**文字**` 显示加粗；命令的 `**/*.swift` 等 shell 语法保留字面内容。
- 移除过程标题上的“有执行异常”汇总标签，避免一次工具失败被误读为整轮任务失败。具体错误、详情及会话权威状态继续保留。
