# 对话消息导航

当前范围：iOS、Web 桌面和移动布局增加左侧消息刻度，点击跳转，手动阅读时更新当前位置；从动态进入会话保留对应消息高亮。刻度悬浮于会话左侧，不预留消息宽度；无背景、间距 10pt/px，选中项最长且邻近刻度逐级缩短。Web 支持悬停/聚焦预览和滚轮选择，触屏支持长按预览与拖动选择；iOS 支持触摸/悬停预览和拖动选择。命令、图片生成等执行过程默认折叠，运行状态不自动展开；用户消息和最终答复中的图片保持消息本身的呈现。

按 R1 实施，复用现有 timeline ID、iOS ActivityDetail 定位和 ExyteChat 滚动接口。iOS 执行组内消息定位到所属显示组；Web 显式定位时展开包含目标消息的折叠活动。列表仅索引当前已加载历史，较早的已加载记录按需展开，云端未加载记录仍使用原有加载入口。导航不写入业务数据，也不改变权限、已读规则或执行状态。

Web 使用同一个 Timeline 渲染器，动态的待审批项优先按原始 itemId 定位，其次使用该轮消息；回答、错误及最终结果沿用当前历史投影。动态定位与刻度点击保持对应颜色，开始手动滚动后恢复可见消息追踪。切换会话清除导航状态。

验证：

- `tests/check_conversation_navigation.cjs`：真实 Chromium 桌面 1280px、移动 390px 下，动态进入的结果高亮、审批消息定位、147 条记录、点击较早消息、展开折叠活动、手动滚动变色、刻度列表自身滚动、预览卡片、渐变长度、透明背景、滚轮选择、执行图片/运行命令默认折叠和 reset 清理通过。截图位于 `.runtime/navigation-1280.png`、`.runtime/navigation-390.png`。
- iOS 完整模拟器构建通过；`tests/run_ios_navigation_regression.py` 在专用模拟器安装独立 bundle 的测试夹具，验证 150 条记录中从动态定位到第 20 条，消费定位目标且实际列表滚动。截图 `.runtime/navigation-regression/navigation.png` 已检查。
- 最终差异、JS 语法检查通过。尚未进行真实设备触摸验收；没有更新正式安装包、提交或部署。

恢复：仅撤回导航界面与对应跳转调用，无数据迁移。保留工作区其他已有修改。

补充验证：iOS Core 85 项测试通过，执行图片的断言已改为保留在执行分组内。

交互微调：刻度长度扩大到前版两倍，滚轮、拖动和悬停临时选择并同步预览；卡片靠近左侧，仅呈现内容，无关闭/跳转按钮，指针移出或触摸结束时隐藏。Web 回归及 iOS 完整构建通过。

性能修复：悬停/滚动预览使用独立的临时选择，不调用正文跳转、历史展开或消息重建；离开恢复原阅读高亮与刻度位置。Web 复用预览节点并按动画帧合并输入，回归覆盖连续 200 次预览不改变正文节点及滚动位置。iOS 拖动仅更新预览，刻度中心索引每轮只计算一次。

布局约定：整个导航条固定在会话区域左侧垂直居中，选中刻度保持原有条内位置；只有选择超出可见范围时最小滚动使其可见，不将选中项居中。Web 已增加整体居中断言。
