## 实现与依据

- 用户首条消息从 turn.params 占位记录切换为原生 userMessage 时，原先展示 ID 不同，列表会删除再插入。现在同一轮首条用户消息保持展示 ID，原生 ID 仍单独保留用于发送回执匹配。iOS 状态行不再因无关 historyRevision 变化重绘。
- 活动摘要优先显示命令、公开思考摘要、查询和文件路径，单行省略；无有效详情时不提供展开箭头。未展示原始 reasoning content。
- 助手正文引用附件转换为绿色文件名链接，通过已有会话附件端点预览，移除正文中已引用附件的重复缩略图/文件列表。未引用的附件仍可访问。
- 用户气泡背景包裹实际文字宽度，外层负责靠右对齐。
- iOS 模型/强度菜单读取本机 Codex models_cache.json 中可见模型及其支持的强度，经已有 settings 操作调整下一轮。缓存缺失时不编造目录。2026-09-14 本机只读检查返回 6 个可见模型。
- compose 的 running 路径通过原生 steer input 发送图片，并在 restoreMessage 保留图片；waiting 路径保留原生队列 imageAttachments。沿用图片大小/数量校验、请求去重、发送前轮次/授权重验。原生 app.asar 中 follower steer 参数及 imageAttachments 的 id/src 结构为协议依据。
- 图片预览从已挂载的 hosting controller 展示；移除会话单元重绘时主动清空已载图片的行为。
- Web 共用稳定消息 ID 和图片发送能力，解除运行/等待状态的附图按钮限制。另外删除 mobile-ui.js 对已不存在 editInput 的残余监听，解决初始化 ReferenceError。
