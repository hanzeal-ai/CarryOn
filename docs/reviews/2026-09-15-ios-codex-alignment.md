# iOS Codex 会话体验统一

## 当前任务契约

目标：沿用 Codex 的状态语义与能力，让手机用户一眼识别执行、等待、队列、完成、失败和中断；使用会话摘要、操作面板和详情页三层布局。

范围：主/子会话与已有临时聊天的状态、执行详情、Agent 活动、队列、审批问答、图片预览与父子返回。复用现有 IPC/HTTP/WS、SwiftUI、ExyteChat、MarkdownUI；不新增依赖、不创建原生侧边聊天、不扩大只读 Agent 权限。

风险 R2：队列及审批写入入口。权威为原生会话快照、请求 ID/fingerprint、queueFingerprint、owner 及后端既有权限检查。客户端仅投影状态，所有写入绑定设备/会话/父关系，迟到响应不得改写其他目标。

已有授权：实现、隔离测试、构建及修复本次引入问题。无提交、推送、部署、真机安装、真实业务消息/审批/队列修改授权。

基线：/tmp/carryon-ios-unify-baseline-20260915 保存实施前 Swift 源码与哈希；当前 checkout 有其他任务的未提交修改，保留它们，不按 HEAD 回退。

恢复：仅撤回本次差异；无数据迁移。真实已执行操作不能通过回滚 UI 撤销。

验收：状态与操作数据契约测试、现有 Swift 测试、完整模拟器构建、隔离 UI 夹具、独立原始证据审查；真实设备/Codex 像素对照需明确验证边界。

## 已实现

- 顶部与活动使用统一状态：执行中、等待批准/回应、队列等待/暂停、已完成、失败、已中断、同步中、状态未知。连接或历史读取失败不得把缓存当成当前完成状态。
- 执行活动默认紧凑，命令、退出码、输出、文件 diff、计划、工具参数/结果进入语义详情页；详情跟随当前快照更新。
- Agent 连续活动聚合，显示名称和实际活动状态；spawn 调用完成不等同于子 Agent 完成。保留单子直达、多子列表及只读边界。
- 输入区旁集中放待回应和队列入口；队列可编辑、删除、排序、恢复暂停项；显式排队复用原生队列。读取失败会显示失败而不是空队列。
- 审批/问答使用底部面板；结构化规则先查看再明确应用；权限提交原请求的准确范围；MCP 基础类型表单保留类型并校验范围，未知/不合法 schema 回原生端处理。
- 写入绑定设备、会话及父子关系；审批/队列等操作等待 native-handler-response，preparing/dispatching 不提前成功；失败保留输入与原请求标识，指纹冲突须用户核对新队列后重试。异步问题需确认投递后才标为已发送。
- 已有临时聊天复用审批、问答、队列、模型设置、图片输入、长按复制和中断重跑；迟到渲染不覆盖更新快照。
- 助手图片附件内联显示，可打开原图；父子返回保存展开项、历史窗口及阅读位置/Agent 锚点（最多缓存 8 个会话）。
