# iOS 会话主线程性能修复

## 范围与边界

用户反馈整页点击、滚动均会卡住。本次为 R1 局部性能修复：调整显示计算与图片工作的执行线程，不改变远程操作、历史内容、缓存容量或发送协议。保留工作区其他未提交功能；不提交、发布或安装到真机。

## 实现

- AppModel 顺序消费实时包，在后台计算历史 JSON 大小，再回主线程更新缓存。后台返回时核验任务取消、登录代次、工作区、会话和历史窗口，丢弃已过期的结果。
- DisplayHistoryCache 接收预先测量的字节数，保持原有 8 项/8 MB、最近使用顺序和超限移除语义。
- 主会话在后台按历史修订分组并复用结果，滚动和输入不重新扫描整个历史。刷新串行合并，过期分组不进入消息列表；临时聊天也在后台分组并校验渲染版本。
- 状态行使用已有消息重绘标识，不再把队列、请求等完整 JSON 编码成消息文本。
- 选图压缩、消息图片解码、附件解码与临时文件写入移到后台。返回 UI 前检查取消；取消的附件清理自己的临时目录。图片尺寸/上传大小限制与预览入口保持不变。

- 最终 iOS Simulator Debug 构建通过（arm64、x86_64），记录 `/tmp/carryon-freeze-build-verified.log`。

- Mac 优化构建模拟数据：约 1.1/4.3/13 MB JSON 编码分别约 8/36/107 ms；现在该编码在后台。主线程缓存插入测量均低于 0.1 ms。这是局部模拟测试，不是端到端或真机帧率。

## 验收限制

尚未捕获用户卡住瞬间的真机调用栈，因此不能确认这些是唯一原因。当前真机未安装修复版；实际持续回复、长历史滚动、选图以及快速切换仍需真机人工验收。若仍卡住，应采集现场主线程堆栈后继续定位。
