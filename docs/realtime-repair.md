# 实时连接、历史加载与性能优化

## 当前实现和影响边界

风险按 R2 处理：修改共享并发、显示投影和实时传输协议。原生状态、轮次、授权与队列指纹仍是写入依据；缓存和本地历史预览只用于展示。无数据迁移、无新增依赖、不自动重试不确定的写入。

- 本地/云端心跳独立计时；慢 HTTP 工作从设备接收循环移出，最多 4 个执行槽跨重连共享，满载返回明确未执行的 503。取消连接时取消未开始工作，执行中的写入继续使用既有授权回调。
- socket 发送不占用桥接全局锁。每个写线程最多一个已通过授权准入的帧在途；已准入的传输不能撤回。
- 原生读取按会话互斥；后台加载最多 4 个任务，不再等待整个侧栏批次，选中会话优先使用下一空闲槽。
- Web/iOS 会话切换复用支持此能力的连接，旧服务端回退重连。选择切换与注册检查同步，避免正常释放旧订阅被误判为断线。
- 追加任务立即回显。原生消息/轮次/队列 ID 核对后清除临时显示；迟到的 HTTP 响应不能恢复已确认消息。失败提示可清除，未知结果不自动重发。
- 后台任务核对只读取目标轮次的原生状态和建会话工具结果，不构建显示时间线；未知证据仍不能判定完成。
- 原生补丁仅复制被修改路径的祖先，保留未变轮次的对象身份。插入值仍独立复制；补丁失败不修改原快照。原生快照携带独立修订号，修订号不依赖缓存是否保留。
- 投影按不可变轮次复用。整份投影缓存至多 8 项、16 MiB 编码内容；对原生完整快照仅保留弱引用。另有 8 MiB 的轮次缓存，计入保留的原生轮次与投影编码内容。通用普通字典调用仍计入原生字典大小。关闭桥接清空缓存，旧构建不能重新填入。上述是缓存预算，不是进程实际内存上限。
- Web/iOS 展示缓存至多 8 项、8 MiB，先比较修订号，避免给相同历史重复编码计量；退出登录清除。Web 复用未变化消息 DOM 和签名，渲染繁忙时只保留最新的完整待处理快照。
- WS 掩码使用 64 KiB 分块的标准库整数 XOR，替代 Python 逐字节循环。双方继续遵循 RFC 6455 的掩码、尾块、帧边界和现有大小限制。

## 首屏、按需加载与增量契约

Web/iOS 默认订阅最近 40 轮；服务端返回 `historyWindow.limit/total/hasMore`。已有“显示更早记录”控制继续展开已下载的记录，新增“加载更早记录”每次扩大 40 轮的服务端窗口。主会话和 Web 临时聊天均支持，各自独立扩大窗口，避免同时拉取另一会话的旧记录。扩大的窗口重新订阅并收到完整基线，时间线仍保持原始轮次顺序和编号；窗口之前的已完成执行时间另行累计，避免总耗时随窗口缩小。

首次没有原生快照时，后台执行既有原生完整历史加载。若本地 rollout 可读取，先展示其有限尾部，标记“正在同步原生历史”，不给出原生操作 controls，也不把预览当作已读证据。原生快照到达后替换预览。原生分页格式没有可用 rollout 时，仍需等待原生快照；本次未臆造原生分页 API，无法承诺缩短 Codex 内部完整历史加载本身。

传输协议由 `historyProtocol: 1` 协商：

1. 首包、切换订阅、重连发送当前窗口的完整 `history/sideHistory`。
2. 后续发送 `historyDelta/sideHistoryDelta`，包括上一份历史的 `base` 修订号、变更字段 `fields`、删除字段 `remove`，以及时间线的 `start/delete/items` 替换段。旧 `messages` 数组使用同样结构的独立替换段。
3. 队列指纹包含在历史修订号中；只有队列改变也必须更新。其他请求、权限和状态字段照常发送。
4. 设备到网关单独通过 `historyWire: 1` 协商。新网关接收每个增量并还原，再保存最新完整状态；HTTP 长轮询消费者仍获得完整投影。网关到浏览器/iOS 独立计算增量，允许中间完整快照被合并。
5. 客户端必须逐包还原后才能合并渲染；基准修订号不符或替换范围无效时关闭连接，重连取得完整基线。新订阅不能使用旧订阅基准。

旧客户端/设备不声明能力时维持完整包。兼容边界集中在上述传输入口，随维护中的 Web、iOS、网关和设备最低版本统一后再移除旧路径；本次没有删除已部署消费者的完整包契约。

- `tests/check_realtime_ui.cjs`：真实 Chromium、模拟 HTTP/WS。即时回显、去重、DOM 复用、缓存切换、断线禁写、真实前端增量解码、扩大历史窗口、缺口重连及完整恢复均通过。运行时指定已安装的 `PLAYWRIGHT_MODULE` 和源码静态预览 `CARRYON_UI_URL`。
- `./iOS/scripts/compile-device.sh` 和不签名 Xcode iphoneos 构建通过；检查应用为 arm64 iOS 可执行文件。
- Python 编译、JS 语法和最终差异空白检查通过。日志位于 `.runtime/performance-*.log`。

原有全量移动视觉脚本含与当前“我的”页面不一致的导航和布局断言，仍未通过，未降低其断言。针对性浏览器通过不替代全量视觉、真实手机或线上验收。

第一阶段真实本地 socket 故障复现记录：修复前 45.0 秒、222 次更新、0 次 ping 后断开；第一阶段修复后 95.16 秒、473 次更新、6 次 ping，保持连接。这不是本轮重新测得的长时间稳定性结果。

## 性能结果及复现

执行 `PYTHONPATH=. python3 tests/benchmark_streaming.py`。基线来自优化前同类合成数据的 `.runtime/performance-review.json`；新结果在 `.runtime/performance-streaming.json`。每轮包含约 240 字符输入、900 字符输出。

| 指标 | 优化前 | 当前 |
| --- | ---: | ---: |
| 1000 轮：补丁应用+显示投影 | 42.1 ms，全历史 | 1.04 ms，最近 40 轮 |
| 4000 轮：补丁应用+显示投影 | 170.4 ms，全历史 | 1.46 ms，最近 40 轮 |
| 4000 轮：首包 | 11.94 MB，全历史 | 172.7 KB，最近 40 轮 |
| 4000 轮：末尾文字更新包 | 11.94 MB，全历史 | 3.4 KB，增量 |
| 约 3.08 MB：单次 WS 掩码 | 196.9 ms | 10.8 ms |

数值为本机合成微基准中位数，不是手机首屏或网络端到端延迟。窗口优化改变首包所包含的历史范围，早期记录通过按需加载获取；不能解读为同一完整历史投影只需 1 ms。展开更多历史后，投影组装与客户端数组处理仍随窗口增长；单轮极大内容仍受现有消息大小限制。
