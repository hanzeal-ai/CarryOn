## 状态权威与恢复

原生桌面的 runtime status 决定是否空闲；新建原生工具结果决定创建 ID；本地数据库只做目录/存在性/创建时间验证，旧 rollout 仅作历史回退。自有 SQLite 保存投递记录，不取代 Codex 的任务状态。

1. 发生异常先取消桥接，停止新的投递。
2. 打开原 Codex 会话核对是否已收到消息或创建了新任务；不要通过删除日志或换 requestId 自动补发。
3. 已知 turnId 的请求在重新桥接、查询 Job 后可重新核验。证据仍不足时，人工核对后使用 acknowledge，仅解除阻塞。
4. 协议升级导致连接/快照异常时，停止 ConnectNow，直接使用 Codex App。恢复不需要修改或替换任何 Codex 文件。
5. 服务 Ctrl+C 或 SIGTERM 会关闭自有连接并释放实例锁；下次启动默认关闭桥接，控制会话需重新选择。

`.runtime` 包含敏感配对 Token 与幂等记录，应保留在本机并排除分发。项目代码可整体移走，停止服务即可撤回本地接入；已创建的 Codex 会话和已执行任务不会随之回滚。
