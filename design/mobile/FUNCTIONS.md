# ConnectNow 移动原型：当前交互契约

仅使用本地演示数据，无真实远程操作。登录凭证为 demo。

| 功能 | 当前入口与行为 |
|---|---|
| 登录、配对码、连接确认 | 登录页与设置中的账户/配对分组 |
| 退出登录 | 设置页面底部独立按钮，确认后退出 |
| 会话搜索与新建 | 首页搜索框、旁边的加号。控制会话直接展示在新建页面 |
| 刷新 | 首页滚动至顶端后下拉，达到阈值后松开刷新 |
| 运行中的任务 | 空输入显示停止按钮，输入文本或选择图片后切为发送 |
| 补充指令与排队 | 运行时发送直接补充；等待请求处理时发送自动进入等待队列，用户不用选择发送方式 |
| 审批与问题 | 在所属对话的消息流中直接展示操作与回答表单 |
| 模型与思考强度 | 发送按钮旁的小按钮打开选择浮层，选择后保留 |
| 执行详情 | 对话内按条展开，无独立显示选项页面 |
| 空闲会话编辑、压缩 | 会话菜单，编辑保留替换确认 |
| 高级设置、临时聊天、元数据、记录 | 会话菜单；临时聊天保持只读 |
| 设备信息 | 顶部展示连接状态；设置保留远程控制与远程待机状态，不提供远程授权开关 |

全局页面取消大标题，保留必要的紧凑导航标题和设备名称。主页与对话不显示设计预览/演示内容提示。演示性质在外部说明中保留。

## 验证

Chromium 已检查停止/发送切换、补充指令、自动等待队列、问题提交与命令审批、模型/强度选择、触摸下拉刷新、图片发送、只读限制与退出。已检查 320/390/430/1280px 的主要页面无横向溢出，关闭按钮宽高一致，并检查了截图。

## 接入边界

原型中的远程待机、模型选项、请求和发送路由均为演示状态。正式接入时必须使用现有原生能力、服务端状态、可用模型列表、请求指纹及幂等约束；等待与补充的裁决不能由 UI 另建权威规则。实机键盘、真实 API 和设备控制尚未验证。

## App 通知设计

- App 内通过会话未读标记、动态事件与角标呈现更新。当前会话直接更新消息，保留输入草稿。
- 点击动态进入所属会话并标记已读；已读不代表批准请求。
- 设置保留新消息、完成、失败、待确认四类通知偏好；系统横幅、声音与锁屏由手机系统管理。
- 不在 App 内制作通知横幅，不提供通知模拟入口。
- 本目录仍为设计原型。真实系统授权、推送与系统通知点击跳转尚未接入，通知偏好仅保留在页面内存中。

## 统一输入组件

新建会话、对话、编辑最后一轮和问题回答共享 conversationComposer。新建/编辑/对话包含附件与模型选择；问题回答沿用同一输入样式，仅提交文本，不增加请求契约不支持的附件或模型字段。JSON 配置保留专用编辑框。已验证控制会话切换保留草稿、空内容禁用、新建、编辑确认、补充/停止与问题提交。

## 工作区卡片

设置页工作区入口并入设备卡片，名称右侧切换；绿在线、灰离线、红异常。连接新工作区按本机填写云端地址发起申请，云端核对名称/时间/确认码后确认或拒绝，确认自动登记并默认只读。动态单列连接申请，移除设备提示撤销凭证和在途操作风险。多云端授权仍由本机逐绑定管理。详细正式功能缺口见 HANDOFF.md。

## 项目与会话层级

会话首页先展示项目，项目内展示并筛选全部/待处理/进行中的会话。项目汇总会话总数、待处理会话数、运行中会话数、未读会话数；有待处理项目优先，其次运行中项目。未读与待处理相互独立。动态按会话去重，仅集中展示需要处理的会话；角标为待处理会话数。对话返回原项目或动态入口。

当前原型按完整演示列表汇总；正式实现必须使用工作区加稳定项目 ID 分组，并从服务端获取全量聚合和分页结果，不能从当前已加载的一页推算项目总数。同名项目不应合并。
